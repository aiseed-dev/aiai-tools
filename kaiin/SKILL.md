# 会員を集めて預かる

あなたは、この会社が会員を集め、その情報を預かる仕組みを作るのを手伝います。会員の情報は、
他人の情報です。預かった会社が責任を持ちます。専門の言葉は、初めて出るときに 1 度説明して
ください。法律の助言はしません。

## 守ること

- 会員の名前、メールアドレス、記録の中身を、AI への依頼に貼りません。あなたも会員の
  データベースを読みません。設計は、項目の名前と件数でできます。テストのデータは架空で作ります
- 預かるのは、使うのに要る物だけにします。何を預かるかは会社が決めます
- 会員が書いた物を外の AI のモデルに送るなら、識別情報(メールアドレス、電話番号、郵便番号、
  12 桁の数字)が入っていないかを送る前に確かめ、入っていたら送らずに戻します。氏名と住所は
  形で見分けられないので、画面で除くよう伝えます。そのことを同意の文に書きます

## 流れ

| | aiai のセカンドオピニオン | 民泊の宿泊者 |
|---|---|---|
| 招待 | 募集に応じた人に、招待の番号を 1 つずつ渡す | 予約した人に、予約の番号かリンクを渡す |
| サインイン | Apple か Google | Apple か Google |
| 同意 | 記録を残すことと研究に使うこと | 名簿に書くこと、本人確認、鍵を出すこと |
| 預かる物 | Apple か Google の ID の番号、確かめたメールアドレス、相談の記録。名前は預からない | 同じ ID とメールアドレスに、名簿の事項([honnin](../honnin/)) |
| 見る、消す | いつでも自分の記録を見られ、すべて消せる | 見られる。名簿は作成から 3 年は消せない(住宅宿泊事業法施行規則第 7 条) |
| 係の人に見える物 | モデルと種類ごとの数と評価の平均だけ | 名簿と泊まり(本人確認と提出のため) |
| お金 | 当面は無料の研究。効果が確かめられたら低い会費 | 宿泊の料金(予約のサイトか、自分で受ける) |

## 調べること

会員の情報は個人情報です。利用目的の示し方、消すこと、安全管理、漏えいのときの報告、本人の求めへの
応じ方、未成年の同意を、個人情報保護法のその時点の条文と、個人情報保護委員会のガイドラインと Q&A で
調べ、同意の文と作りに入れます。2026-07-17 公布の改正法(16 歳未満の同意など)が施行されたら、
調べ直します。

## 手順

1. 何の会員かを聞きます。招待のしかた(募集か予約か)、預かる物、記録を残す期間、消さずに
   残す物があるか(法令で決まった物、安全のために残す物)、係の人が何を見るか
2. 同意の文を書きます。預かる物、使う目的、外に送る先(AI のモデルの会社など)、本人が見て
   消せること、消せない物があればその期間。会社の言葉で書き、会社の人が決めます。文には版を
   付け、変えたら同意を取り直します
3. 招待を作ります。番号は、読み違えにくい文字(0 と O、1 と I と L を除く)で作り、1 つにつき
   1 人だけが使えるようにし、データベースにはハッシュで置きます。使ったときに印を付けます
4. サインインは Apple か Google にします([ninshou](../ninshou/))。預かるのは、ID の番号と、
   Apple か Google が確かめたメールアドレスです
5. 使えるかを毎回確かめます。招待を使った人で、今の版の同意をした人だけが使えるようにします
6. 本人の画面を作ります。自分の記録をすべて見られること、すべて消せること。消さずに残す物
   (法令で決まった物、安全のために残す物)は分けて置き、期間が来たら毎日の仕事で消します
7. 係の人の画面を作ります。aiai のセカンドオピニオンのように、数と平均だけで足りるなら、
   中身を見られないようにします。係の人は、メールアドレスの一覧(環境の変数)で決めます
8. 漏えいのときの手順と、会社の名前や窓口を書いたページを、先に用意します

## 作り方

- aiai の [soudan](https://github.com/aiseed-dev/aiai/tree/main/soudan) が、動く例です。
  サインインは [moushikomi](https://github.com/aiseed-dev/aiai/tree/main/moushikomi) の確かめ済みの物
  を使い、`people`(ID、メールアドレス、同意した版と日時、使った招待)と `invites`(番号の
  ハッシュ、使った日時)の表を持ちます。偽の Apple と Google を相手に、招待、同意、記録を消す
  までを確かめるテストがあります
- PocketBase で作るなら、会員を auth のコレクション(`members`)に置き、`invites` のコレクション
  (番号のハッシュ、使った日時)と、`members` に同意の版と日時の欄を足します。API ルールで、
  本人は自分の分だけ(`id = @request.auth.id`)、係の人は役割で見られるようにし、本人が役割を
  書き換えられないよう `@request.body.role:isset = false` を足します。PocketBase には書き出しの
  道具が無いので、本人の分を出す仕組みは自分で作ります
- 会費を取ると決めたら、決済と、そのときの表示の決まりを、そのときに調べます

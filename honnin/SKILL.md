# 本人確認(民泊と宿泊)

あなたは、この会社が、宿泊者の本人確認と宿泊者名簿を自分のアプリで受けるのを手伝います。
専門の言葉は、初めて出るときに 1 度説明してください。法律の助言はしません。条文と
官庁の文書に書いてあることを示し、決めるのは会社です。

## 守ること

- 宿泊者の名前、住所、旅券の画像を、AI への依頼に貼りません。あなたも、名簿のデータベースと
  画像を読みません。設計は、項目の名前と件数でできます
- 旅券の写しと名簿は個人データです。見られる人を絞り(API ルール)、保存の期間が過ぎたら
  消します(個人情報保護法第 22 条、第 23 条)
- 自治体の条例で上乗せがあることがあります。届出の先の自治体の決まりを、会社の人が確かめます

## 調べること

宿泊者名簿に書く事項、保存の期間、本人確認の方法、外国人の旅券の写しは、住宅宿泊事業法と旅館業法の、
その時点の条文、施行規則、ガイドライン、FAQ で調べ、名簿の形と確かめ方に入れます。民泊と簡易宿所で
違います。名簿の責任は、事業者(委託したら管理業者)にあり、Airbnb などの仲介業者にはありません。

## 手順

1. どちらの制度かを聞きます。民泊か簡易宿所か、管理業者に委託しているか、どの自治体か、
   部屋の数、外国の宿泊者がいるか
2. 名簿の形を決めます。PocketBase([ninshou](../ninshou/))に、泊まり(予約)を 1 件とし、
   宿泊者を 1 人 1 件で持ちます
   * `stays`: 宿泊日(入る日、出る日)、部屋、状態(予約、確認済み、チェックイン、チェックアウト)
   * `guests`: 泊まり、氏名、住所、職業(民泊)または連絡先(簡易宿所)、国籍、旅券番号、
     旅券の写し(ファイルの欄を Protected にする)、確認した人、確認した日時、確認の方法
   * API ルールは、見るのも書くのも、会社の係の人(`@request.auth.role = "staff"`)だけにします。
     宿泊者が前もって自分の分を入れる画面を作るときは、作ることだけを許し、後から読めないようにします
3. 前もって入れてもらいます。予約の後、宿泊者に予約の番号かリンクを知らせ([tsuuchi](../tsuuchi/))、
   サインインと同意の後に([kaiin](../kaiin/))、全員の名前などを入れてもらいます。入れた物は
   下書きで、チェックインのときに本人と一緒に確かめます(旅館業の FAQ も、予約のときの情報を
   使い、チェックインのときに宿泊者が確かめる形を示しています)
4. チェックインで本人確認をします
   * 民泊: ビデオ通話で、宿泊者全員の顔と旅券を確かめます。住宅に置いた据え置きのタブレットから
     つなぐと、住宅から送られていることを確かめやすくなります。ビデオ通話は、自分の側に置いた
     Jitsi([kaigi](../kaigi/))でできます。係の人が確かめたら、`guests` の確認の欄を埋めます
   * 簡易宿所: 上と同じ方法か、自動チェックイン機器の方法です。機器の方法は、事前の本人確認の
     情報(氏名、住所、連絡先)と二次元コードなどを照らし合わせ、様子を顔が分かる角度で録画し、
     問い合わせに応じる体制を置きます(録画は今ある防犯カメラでよい、と厚労省の FAQ にあります)
   * 旅券の写しを撮ります。日本に住所のない外国人の宿泊者だけです。ビデオ通話の画面から
     写しを取ってよいかは、確かめていません。迷ったら、届出の先の自治体に聞きます
5. 鍵を渡します。本人確認が済んだ泊まりにだけ、泊まる間だけ使える鍵を出します([kagi](../kagi/))
6. 名簿を出せるようにします。知事などの求めに応じて、泊まりごとの名簿を紙か PDF に出せる画面を
   作ります
7. 消します。作成の日から 3 年たった名簿と旅券の写しを消す仕事を、PocketBase の cron で
   毎日動かします。消す前に、保存の期間を会社の人が決めて書いておきます

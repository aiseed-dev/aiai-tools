= 毎日の点検(tenken)利用者マニュアル

毎朝 6 時に、会社のネットワークの機器に当たる弱点の知らせと、機器の記録が届いているかを、1 つの知らせに
まとめます。読むのは、記録の機械の `~/tenken/` の、その日のファイルか、届いたメールです。

== 初めにすること

. 記録の機械に、`tenken.py` を `~/tenken/` に置きます
. `kiki.csv.example` を `~/tenken/kiki.csv` に写し、会社の機器を 1 行に 1 台ずつ書きます
** 名前: 会社で呼んでいる名前(例: 本社の境界のルーター)
** メーカー、製品: 説明書にある名前。CISA と JVN の書き方が違うときは `|` で区切って両方書きます
   (例: `Yamaha|ヤマハ`、`RTX830|RTX シリーズ`)
** 版: ファームウェアの版。分からなければ空にします
** 記録: 記録の機械の上の、その機器の記録のファイル。無ければ空にします
. 知らせをメールで受けたいときや、AI に所見を書かせたいときは、`tenken.env.example` を `~/tenken/tenken.env` に
  写して書きます
. 毎朝動くようにします
+
----
mkdir -p ~/.config/systemd/user
cp systemd/tenken.service systemd/tenken.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now tenken.timer
sudo loginctl enable-linger $USER
----
+
最後の行は、サインインしていないときも動くようにするための物です
. 1 度、手で動かして、知らせが出るかを見ます
+
----
python3 ~/tenken/tenken.py
----

初めての点検では、前から一覧に載っていて会社の機器に当たる物を、1 度だけ並べます。

== 毎朝すること

その日の知らせ(`~/tenken/YYYY-MM-DD.adoc` か、メール)を読みます。

* 1 行だけなら、することはありません
* 「新しく当たった知らせ」があれば、出典の URL で、会社の機器の版が当たるかを確かめます。当たれば、
  メーカーの手順で更新するか、知らせにある手当てをします
* 「記録が届いているか」に「届いていない」「無い」があれば、その機器と記録の機械のつながりを確かめます
* 「取れなかった知らせ」があれば、記録の機械から CISA と JVN に届くかを確かめます。次の朝も同じなら、
  担当の人に伝えます

== 機器を足したり替えたりしたとき

`kiki.csv` を直します。次の朝から、その機器に当たる物を見ます。足した機器に前から当たっている物は、1 度だけ並べます。
